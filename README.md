# Customer Churn Prediction

A small, reproducible machine learning project that predicts which telecom customers are likely to cancel their subscription (**churn**). The goal is to let a retention team contact at-risk customers *before* they leave.

The project is structured like a real AI project: reusable code, a documented experiment notebook, a design decision log, and version-control conventions.

## Dataset

**IBM Telco Customer Churn** — one row per customer of a fictional telecom company.

| Group | Columns |
|---|---|
| Identifier | `customerID` (not used as a feature) |
| Demographics | `gender`, `SeniorCitizen`, `Partner`, `Dependents` |
| Services | `PhoneService`, `MultipleLines`, `InternetService`, `OnlineSecurity`, `OnlineBackup`, `DeviceProtection`, `TechSupport`, `StreamingTV`, `StreamingMovies` |
| Account | `tenure` (months), `Contract`, `PaperlessBilling`, `PaymentMethod`, `MonthlyCharges`, `TotalCharges` |
| **Target** | `Churn` — Yes / No |

Key facts:

- **7,043 customers**, 19 usable features (3 numeric, 16 categorical).
- **Imbalanced target:** 26.5% churn, 73.5% stay.
- **Data issue:** `TotalCharges` has 11 blank values, all for brand-new customers (tenure = 0). They are set to 0 (see `decision_log.txt`, Decision 4).

---

## Machine Learning Model

**Final model:** Logistic Regression with `class_weight="balanced"`, inside a scikit-learn `Pipeline`:

1. `StandardScaler` on numeric features (`tenure`, `MonthlyCharges`, `TotalCharges`)
2. `OneHotEncoder` on the 16 categorical features
3. `LogisticRegression(class_weight="balanced")`

Five models were compared with 5-fold stratified cross-validation — a majority-class baseline, Logistic Regression (with and without class balancing), a Decision Tree and a Random Forest. The balanced Logistic Regression was chosen because it caught the most churners with the best F1-score, while staying simple and interpretable. Full reasoning is in [`decision_log.txt`](decision_log.txt).

## How to Run

**1. Clone the repository**

```bash
git clone https://github.com/sherjaan707-sudo/churn-prediction.git
cd churn-prediction
```

**2. Create a virtual environment and install dependencies**

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
```

**Alternative to step 2 — using [uv](https://docs.astral.sh/uv/) (faster, exact versions)**

`pyproject.toml` declares the dependencies and `uv.lock` pins the exact version of every package, so everyone gets an identical environment.

```bash
pip install uv          # one-time
uv sync                 # creates .venv and installs the locked versions
uv run jupyter notebook notebooks/churn_experiment.ipynb
uv run python models/model.py
```

**3. Run the experiment notebook**

```bash
jupyter notebook notebooks/churn_experiment.ipynb
```

Then choose **Kernel → Restart & Run All**. The notebook regenerates every chart and table in `reports/`.

**4. (Optional) Train and evaluate the final model from the command line**

```bash
python models/model.py
```

All randomness is fixed with `random_state=42`, so results are reproducible.

## Results Summary

**Cross-validation (training set, 5 folds)**

| Model | Accuracy | Recall | F1 | ROC-AUC |
|---|---|---|---|---|
| Baseline (majority class) | 0.735 | 0.000 | 0.000 | 0.500 |
| Logistic Regression | 0.802 | 0.544 | 0.592 | 0.846 |
| **Logistic Regression (balanced)** | 0.748 | **0.801** | **0.628** | **0.846** |
| Decision Tree | 0.791 | 0.513 | 0.565 | 0.829 |
| Random Forest | 0.804 | 0.498 | 0.574 | 0.845 |

**Final model on the held-out test set (1,409 customers)**

| Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|
| 0.738 | 0.504 | 0.783 | 0.614 | 0.842 |

**What this means**

- The model finds **about 78% of customers who will churn**. Unweighted models found only ~50–55%.
- The trade-off: about half of flagged customers would not actually have left (precision 0.50). For retention, a discount given to a loyal customer is usually far cheaper than losing one, so this is an acceptable trade-off.
- The strongest churn signals are **month-to-month contracts**, **short tenure** and **fibre-optic internet**; two-year contracts and long tenure strongly reduce risk.
- Test scores are close to cross-validation scores, so the model generalises well.
- A majority-class baseline already reaches 73.5% accuracy, which is why F1 and recall — not accuracy — were used to choose the model.

## Version Control

The project uses a simple feature-branch workflow: `main` always holds working, reviewed code, and each piece of work happens on its own branch that is merged through a pull request.

```
branch: main
Stable version of the project. Only updated through reviewed pull requests.

branch: data-cleaning
Used for fixing the TotalCharges data type and blank values, and moving
cleaning logic into models/model.py.

branch: model-comparison-experiment
Used for testing new models (Decision Tree, Random Forest, balanced
Logistic Regression) against the baseline with cross-validation.

branch: feature-selection-experiment
Used for testing whether removing low-signal features (gender, PhoneService)
improves the model.

branch: update-readme
Used for improving documentation: README results, run instructions and
the decision log.
```

**Commit message style** — short, present tense, describing what changed:

```
Add stratified train/test split and CV helper
Fix blank TotalCharges values for tenure-0 customers
Add balanced Logistic Regression to model comparison
Update README with test-set results
```

## Pull Request Example

```
Title: Improve churn detection with balanced Logistic Regression

Branch: model-comparison-experiment → main

Summary:
The original Logistic Regression model reached 80% accuracy but missed
almost half of the customers who actually churned (recall 0.54). Because the
business goal is to find at-risk customers, this PR compares several models
using churn-focused metrics and switches the final model to Logistic
Regression with balanced class weights.

Why:
Only 26.5% of customers churn, so an unweighted model is biased towards
predicting "no churn". Accuracy hides this — a model that never predicts
churn is already 73.5% accurate. Class balancing makes the model pay more
attention to churners.

Changes:
- Added get_candidate_models() to models/model.py (baseline, 2× Logistic
  Regression, Decision Tree, Random Forest)
- Added 5-fold stratified cross-validation comparison to the notebook
- Changed the primary evaluation metric from accuracy to F1 (churn class)
- Changed build_final_model() to use class_weight="balanced"
- Added Decisions 1 and 2 to decision_log.txt
- Updated README results section

Results (5-fold CV on training set):
- Recall improved from 0.544 to 0.801 (+47% more churners caught)
- F1 improved from 0.592 to 0.628
- ROC-AUC unchanged at 0.846
- Accuracy decreased from 0.802 to 0.748 (expected trade-off, see decision log)
- Held-out test set: recall 0.783, F1 0.614, ROC-AUC 0.842

How to test:
Run notebooks/churn_experiment.ipynb with "Restart & Run All", or run
python models/model.py.
```
